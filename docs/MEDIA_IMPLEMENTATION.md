# Media transport source handoff

Prepared source: integration **1.8.0**, HA app **0.2.4**. M1 and M2 are ready
for consumer development against the synthetic contract. Deployment and a live
WhatsApp trial remain separate. Nothing here installs or activates a consumer.

## Discovery and implementation

Work started from source `15b925d083ac0399012a8c08f9874737f2fae3a4`;
the refreshed remote default branch was its merged descendant
`7824ce2` (PR [#3](https://github.com/sebastian-greco/home-assistant-whatsapp/pull/3)).
The starting integration/app versions were 1.7.0/0.2.3. An all-state issue
search found only the existing installation and group-recipient issues; no
open or closed media issue existed. This extends the existing channel,
group/guest routing, observations and durable send ledger rather than adding
a second transport or new repository.

- **M1:** additive attachment metadata, explicit GOWS `ptt`/`audio` facts,
  persisted exact bindings, bounded on-demand retrieval and HA binary route.
- **M2:** authenticated staging, native image/file/voice submission, shared
  content-based correlation, accepted replay after byte expiry, and uncertain
  send fences.
- **M3:** adversarial and baseline regressions, independent Astra High review,
  API/fixture publication and release preparation. No release tag or runtime
  deployment is part of this source handoff.

The [normative API](MEDIA_API.md) defines final schemas, HTTP paths,
authentication, capabilities, limits, errors and supported formats. The
[JSON fixtures](examples/media-v1.json) and
[binary hashes](examples/media-fixtures/SHA256SUMS) are synthetic. The proposed
action and route names are preserved. Stricter bounds and unsupported formats
are called out in the API's deviations section.

## Backend and app requirements

The engine remains **GOWS 2026.9.1**, pinned as
`devlikeapro/waha:gows-2026.9.1@sha256:5a56c7610bd42336874efac3e2e43e51d7893f3274dcef73f27fa3120da134d6`.
Upstream 2026.9.2 existed at discovery; this work requires no engine upgrade
or downgrade. The conservative integration floor is GOWS 2026.9.1.

The app source change sets `WAHA_BASE_URL` to the same private origin
advertised by Supervisor discovery. Without it, the previous listener address
could become an unusable media URL. External servers must configure that base
to match the integration's configured origin. Origin mismatches fail closed;
the integration does not follow arbitrary aliases or redirects.

Keep `download_media: false`: event/API defaults and the deprecated fallback
stay false. One authorized message request explicitly sets
`downloadMedia=true`. Local WAHA media storage is `/data/media`, with the
app's independent 86400-second lifetime; HA-owned references/files have the
fixed one-hour window and integration-wide quotas in the API. No unrelated
chats or history are downloaded. No new Python dependency is required.

## Review and validation

Independent **gpt-6-astra, high reasoning** review was used throughout. Fixed
findings include permission revocation during queued/prepared transfers,
administrator/runtime replacement before binary release, guest membership
changes during inbound persistence, PTT metadata without a downloaded media
object, cancellation-safe cleanup/accounting, and durable file/index commits.
Regression tests exercise the corresponding waits and failures.

Local checks passed: **581 Python tests** with installed HA 2026.7.2 libraries;
the repository-only environment passed **525**, with **11** HA-dependent skips.
Ruff, compilation, version/tag consistency, JavaScript syntax and all **20** app
JavaScript tests passed. HTTP tests use isolated
localhost servers and generated bytes. They are not a passed live HA/WhatsApp
end-to-end test.

The local Docker daemon was unavailable, so the real-image unlinked-container
smoke test could not run locally. The PR app build workflow runs that isolated
smoke gate before any image publication. CI-only HACS/hassfest/app-lint results
must also be inspected before release. No live app was started for validation.

## Activation, disable and rollback

The originating HA session owns release installation, app update/restart,
option activation, central household egress changes and consumer deployment.
Use the [short live checklist](MEDIA_HA_TEST.md), starting with a voice note
and a normal same-chat text reply; record latency and peak RAM there.

Disabling the media option fences future transfers while ordinary text,
notifications, polls and commands remain available. It preserves private
references, bytes until fixed expiry, and durable receipts. Access revocation
cannot erase copies already retained by an external consumer.

Preserve integration `.storage` data and the WAHA `/data` session backup.
Prefer disabling media over rolling source backward. The older send-ledger
reader does not understand media records and can fail closed; do not delete
or reset that ledger to force a downgrade. Quiesce/reconcile outstanding
pending/unknown sends before any restore or rollback, preserve their receipts,
and use matching backups. Never create a fresh request ID merely because a
submission's outcome is unknown. The unchanged engine pin does not constitute
a tested live app/session rollback.

Native voice accepts validated Ogg/Opus without conversion. Other supported
audio sends as an attachment; documents are PDF only. Non-Ogg containers have
signature recognition rather than full decoding. There is no STT, TTS,
transcript, agent execution, policy/memory store or credential integration.
